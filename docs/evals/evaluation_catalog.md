## Counts, duplicates and preferred locations

Prefer the existing tracked dataset in `FinSearch-semantic-benchmark-v2` when that exact logical file and byte version is available. Legacy-only files stay in `FinSearch-reboot/data/evals`. `preferred_existing_copy` matches SHA-256, artifact role and normalized worktree-relative path; checkpoint suffixes are normalized before matching. It then prefers a non-checkpoint dataset under `data/evals`, the documentation worktree and tracked content, in that order. Different runner variants and result snapshots remain distinct even when their bytes match. Each SHA-based group is classified as `logical_copies` or `byte_equal_distinct_artifacts`; the latter is byte identity only, not interchangeability or additional coverage. No dataset moved. Versions with different hashes remain separate even when questions overlap. Identical configurations across editions do not make their labels identical. Empty result logs may share a hash without representing dataset copies.

- Retrieval v3 and v2 each contain 126 dataset rows, with 120 scored cases and six exclusions. The 948-row corpus is document coverage, not query coverage. V3 has 231 label-change records, not 231 new cases.
- The chunking source has 40 questions; its CSV is an alternate representation, not a byte duplicate. Seven derived JSONL variants have 50 or 51 records each. The converter expands cross-year questions and collapses graded qrels; these cannot be summed as independent coverage. Byte-identical flat/structure runner variants and checkpoint copies are grouped by SHA-256.
- Legacy SP100 editions: thesis v3 = 230 rows; thesis v4.1 and v4.3 = 353 each; query v4.1 and v4.3 = 353 each; full query file = 403; combined document index = 6,248 documents. The two v4.3 qrels files each have 713 parsed relations, not 713 questions. The 16-question original and runner files each have 16 rows but different bytes.
- Other legacy files: ChatGPT set = 50 rows; Claude set = 35; AMZN/GOOGL planner labels = 50; metadata hardmode = 116. None has newly established gold validity or scored-case coverage.
- The empty `agents/.ipynb_checkpoints/planner_routing_core.v1-checkpoint.json` is malformed JSON. It was backed up and stays explicitly unvalidated. TSV/CSV header handling and JSON container count bases are recorded; absent counts are unknown, never zero by assumption.
